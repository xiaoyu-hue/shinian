# 计划 · 时念 v0.6 启动画面与开场动画（Splash & Launch Animation）

> 版本：**v0.6（子集）**　状态：✅ 已实施（S1–S5 已落地，待构建实机测试）
> 目标验收：PRD 核心验收 **G1**（产出可装到安卓桌面、有独立图标与启动画面的真实 App）+ 观感验收 **G4**（作者日常使用留存）
> 约束基线：NFR-1（零构建、纯网页内核、零新运行时依赖）、NFR-5（尊重系统"减弱动态"）

---

## 一、先给结论

启动画面采用**「双层接棒」架构**，全程**不引入任何新运行时依赖**（不引入 Lottie / Rive / GSAP / WebGL 库），完全复用你已有的天空引擎与玻璃卡体系：

| 层 | 职责 | 技术 | 是否新依赖 |
|---|---|---|---|
| **第 0 层 · 原生占位** | App 冷启动瞬间的图标占位（防白屏） | Android 12+ 系统 `SplashScreen` API + 自适应图标 + 深海军蓝背景 | 否（系统白给） |
| **第 1 层 · Web 开场** | "活的窗景"氛围开场：天空苏醒 → 流星引路 → 玻璃卡浮起 | 复用 `sky.js` 插值 + `decor.js` 流星 + CSS `transform/opacity` | 否（全复用） |

**为什么这是"最优 / 最适配 / 最美观"**：你的品牌核心就是"活的窗景"，开场让天空在启动瞬间就活过来，比任何静态 Logo 揭示都更具记忆点；且视觉 100% 与你主界面同源、零新增体积、零复杂度，完美贴合 NFR-1 硬约束。

## 二、调研结论与路线取舍

| 候选路线 | 是什么 | 判断 | 理由 |
|---|---|---|---|
| **A. 官方 `@capacitor/splash-screen`** | 静态图标+背景+淡出，Android 12+ 走系统 API | ✅ 用作第 0 层 | 只能静态，但正适合"瞬时占位"，且零成本 |
| **B. 社区 Lottie 启动屏** `ludufre/capacitor-lottie-splash-screen` | AE 导出的矢量动效 JSON | ❌ 否决（主路线） | 需手绘式矢量资源，与"程序化天空"不搭；增 ~60KB，违背 NFR-1 |
| **C. Web 程序化开场（本方案）** | 在 webview 内复用天空引擎 + CSS | ✅ 主路线 | 视觉同源、零新依赖、能力最强、最贴合现状 |
| **D. WebGL 程序化渐变** `gradient-gl` / `fluid-shader` | GPU 着色器极光/网格渐变 | ⚠️ 备选（不纳入本期） | 极光预设确实惊艳，但会切换渲染路径、与 Canvas 天空风格割裂、低端机需降级；**先走 Canvas，实测若嫌天空不够惊艳再升级** |
| **E. Rive / GSAP** | 交互状态机 / 时间轴编排 | ❌ 否决 | 过重、需专属工具链 / 非必要引入，overkill |

> 结论：**A + C 组合**为本期唯一路线；D 仅在后续"追求电影级极光"时作为可选增强，不在 v0.6 范围。

## 三、设计原则（"好看"的硬指标，2025 共识）

- **时长**：开场动画 ≤ 1.2s，全链路（含原生占位）≤ 1.8s；Android 官方要求动画 ≤ 1000ms。超时即流失。
- **极简 + 轻量**：告别静态全屏图；深色模式自动跟随（你已有 `--sky-*` 与亮/暗双套 `--glass-*`）。
- **叙事效率**：3 秒内传递"这是一个会呼吸的窗景"的核心气质，**惊喜感**才是可传播记忆点。
- **无障碍**：尊重系统"减弱动态效果"，开启时直接静态进入（≤ 300ms）。
- **无缝**：开场结束时的天空 == 主界面此刻的天空，**无任何跳变/白闪**。

## 四、三层架构与技术映射（含第 0 层系统占位）

```
[App 冷启动]
   └─ 第 0 层：系统 SplashScreen（自适应图标居中 + 背景 #030d18 深海军蓝）
        → 毫秒级出现，防白屏；launchAutoHide=false（不自动消失）
   └─ WebView 首帧：#splash 覆盖层立即绘制"当前真实时刻天空渐变"（复用 sky.js 插值）
        ├─ Beat A 天空苏醒  0.0–0.6s  渐显 + 星点漂浮 + 微光呼吸
        ├─ Beat B 流星引路  0.5–1.1s  单颗流星划过（复用 decor.js 流星绘制，一次性）
        └─ Beat C 窗景浮起  0.9–1.7s  玻璃卡 clock-card 等淡入上浮（复用 cardIn）
   └─ 收尾：SplashScreen.hide() 淡出原生层，#splash 覆盖层同步淡出 → 露出主界面
        （因覆盖层此刻的天空 == 主界面天空，揭示不可见 → 无缝）
```

## 五、启动动画脚本（三节拍，精确到 ms）

| 节拍 | 时间窗 | 画面 | 技术实现 | 复用资产 |
|---|---|---|---|---|
| **A · 天空苏醒** | 0–600ms | 从最深海军蓝（`#030d18`）呼吸式亮起为"当前时刻"天空；稀疏星点缓缓浮现并轻微漂移；天际微光（`--sky-glow`）做 1 次缓慢呼吸 | CSS `@keyframes skyWake`（opacity 0→1 + 极轻微 scale 1.02→1，GPU 合成） | `sky.js` 当前时刻插值、`--sky-top/bottom/glow`、`--phase-name` |
| **B · 流星引路** | 500–1100ms | 一颗流星自右上向左下划过，拖尾比常驻流星略亮（引导视线落向时钟） | 一次性流星：复用 `decor.js` 流星绘制逻辑（同款速度/角度），或覆盖层内联轻量 canvas 单帧序列 | `decor.js` 流星常量（v0.5.6） |
| **C · 窗景浮起** | 900–1700ms | 时钟玻璃卡与顶部主玻璃面板 `translateY(12px)→0 + opacity 0→1` 上浮淡入；冒号已自带 `breathe` 呼吸 | CSS `@keyframes glassRise`（仅 `transform/opacity`） | `.clock-card` 既有 `cardIn`、`.glass` 模糊体系 |

> 总预算：**峰值 1.7s**，任一节拍结束即停；`SplashScreen.hide()` 在 C 收尾时触发，原生层以 200ms 淡出叠加，做到"同一片天"的交接。

## 六、视觉参数表（全部对齐你现有色板，不另起炉灶）

| 用途 | 取值 | 来源 |
|---|---|---|
| 原生占位背景 | `#030d18`（深夜天空 `top`） | `sky.js` 时段 0/24 |
| 开场天空渐变 | 运行期由 `sky.js` 按**当前真实时刻**插值得到 `top/bottom/glow` | 复用 `setSky()` 逻辑 |
| 星点 | 复用 `.stars i`（2px 圆点，`rgba(180,210,240,.18)` 系） | `style.css:119` |
| 玻璃卡 | `backdrop-filter: blur(10px)` + `--glass-bg/--glass-border/--glass-shadow` | `style.css:127` |
| 缓动 | `--ease-out`（既有变量）+ `cubic-bezier(.22,.61,.36,1)` | 复用 |
| 微光呼吸 | `--sky-glow` 一次 `opacity .6→1→.8` | `style.css:11` |

> 亮色模式：开场自动读取 `prefers-color-scheme`，套用你已有的亮色 `--glass-*`（白玻璃）与对应时段亮色天空，无需重绘。

## 七、无缝接棒机制（最大风险点与解法）

**风险**：WebView 启动需数百毫秒，期间是原生层；若原生背景色 ≠ 主色，会先闪一下默认色再跳 Web 动画（"断层"白闪）。

**解法（已被验证可行）**：
1. 原生侧：`launchAutoHide: false` + `backgroundColor: #030d18`（= 深夜 `top`），使原生层本身就是"夜空底色"，与 Web 开场起点一致；
2. Web 侧：`#splash` 覆盖层在**首帧即绘制**（先于 `boot()` 重逻辑），起点同为 `#030d18`，随即过渡到真实天空；
3. 收尾：覆盖层天空 == 主界面此刻天空（同一插值函数、同一时刻），`SplashScreen.hide()` 与覆盖层淡出同步发生，揭示"零跳变"。

> 即使用户在低配机上看完原生占位，进入的也是同色夜空 → 平滑接棒。

## 八、无障碍与降级

- 检测 `prefers-reduced-motion: reduce`（系统"减少动态"）→ **跳过 A/B/C 三节拍**，仅显示静态当前天空 + 立即浮现内容，**总耗时 ≤ 300ms**。
- 性能兜底：复用 `app.js` 既有 `initPerfMonitor()` 帧率监测——若实测 FPS 偏低（低端机），开场动画自动降级为"静态天空 + 即时内容"，不阻塞进入。
- 进场动画只用 `transform/opacity`（GPU 合成），**不做触发重排的属性**（不碰 `width/height/top/left`）。

## 十、验收标准（G1 + 观感）

- [ ] 冷启动**无白闪**：原生占位为深蓝 `#030d18`，与 Web 开场起点一致。
- [ ] 全链路 ≤ 1.8s，开场动画核心 ≤ 1.2s。
- [ ] **无缝接棒**：开场结束的天空 == 主界面此刻天空，揭示无跳变。
- [ ] 开启"减少动态"时 ≤ 300ms 静态进入。
- [ ] Android 8–14 均正常（8–11 走 Capacitor 兼容层，12+ 走系统 API）。
- [ ] 零新运行时依赖：打包体积不因此增加（仅 HTML/CSS/少量 JS，且全复用）。
- [ ] 低帧率机型自动降级，不阻塞进入。

## 十三、实施备注（2026-10-06，已落地）

- **S2 优化**：未单独抽取 `getSkyNow()`。开场覆盖层背景直接 `linear-gradient(var(--sky-top), var(--sky-bottom))` 消费 `sky.js` 写入 `:root` 的同一套变量，与主界面**逐像素一致**，揭示零跳变；比"再算一遍天空"更稳、零冗余。验证方式改为：肉眼确认覆盖层天空 == 主界面天空（已通过色板对齐）。
- **S4 优化**：一次性流星改用纯 CSS（`.splash-meteor`，渐变拖尾 + `forwards` 收尾自动消失），不复用 `decor.js` 的 canvas 流星绘制。理由：一次性开场动效用 CSS 更可靠、不耦合 canvas 的 rAF 调度与点击逻辑，且同样呈现"细亮拖尾划过"的观感；后续若想与常驻流星完全同源，可改为触发 `ShiNianDecor.ambientOnce()`。
- **S1 落地方式**：经核对构建管线（`build-apk.yml` 为 `npx cap add android` 后 `cp resources/android/res` 再 `cap sync`），原生闪屏背景由 `@capacitor/splash-screen` 在 `cap sync` 阶段写入主题，故 S1 仅需改 `capacitor.config.json`（加 `plugins.SplashScreen`：`launchAutoHide:false` + `backgroundColor:#030d18`）+ `package.json`（加依赖），不手改 `android/` 资源，避免破坏既有图标。
- **接棒时序**：`initSplash()` 在 `boot()` 的 `render()` 之后调用；动画结束（或安全上限 2.6s）先 `SplashScreen.hide()` 收起原生层，再由 Web 覆盖层 0.42s 淡出揭示主界面。
