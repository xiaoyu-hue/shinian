## v0.2 核心目标

**天空从"时钟驱动"升级为"天文驱动"。**

v0.1 的天空锚点是死的——黎明固定 6:18、日落固定 18:24，冬天和夏天没区别。
v0.2 用真实的日出日落时间替换硬编码锚点，让天空真正"活着"。
同一时刻，冬天的傍晚和夏天的傍晚看到不一样的天。

同时接入实时天气，在天空上叠加阴/晴/雨/雪的视觉装饰层。

## 技术架构（v0.2 增量）

```
时念/
├── index.html              # 单页入口（新增：城市选择器、天气图标区）
├── assets/
│   ├── style.css           # 新增：天气装饰层样式、城市选择器样式
│   ├── sky.js              # 升级：硬编码锚点 → 动态锚点（日出日落驱动）
│   ├── app.js              # 新增：城市管理 UI + 天气获取入口
│   └── weather.js          # 新增：Open-Meteo 接口层（请求/解析/缓存/降级）
└── data/
    └── cities.json         # 新增：中国主要城市坐标列表
```

**数据流（单次刷新）**：

```
用户打开/每分钟 → weather.js 请求 Open-Meteo
                          ↓
              解析日出日落 + 天气代码 + 当前温度
                          ↓
             sky.js 接收新锚点，更新时间段映射
                          ↓
              天气代码 → 装饰层开关（雨丝/雪花/阴云）
                          ↓
              CSS 变量更新，页面重绘
                          ↓
              网络失败 → 回退 v0.1 纯时间模式
```

## 分阶段计划

### Phase 0 · 城市数据与选择器

| 项 | 内容 |
|---|---|
| 任务 | ① 收集中国主要城市经纬度（省会 + 直辖市 + 热门城市，约 40 个）；② 写 `data/cities.json`，格式 `{name, lat, lon, pinyin}`；③ 建城市选择 UI：页面顶部或底部一行文字 + 下拉/搜索；④ 选中城市写入 `localStorage['shinian.city']`；⑤ 默认北京 |
| 产出 | `data/cities.json`；城市选择器可切换并持久化 |
| 验证 | 切换城市后刷新页面，选择保留；切换城市后触发天气重拉 |
| 回退 | 删除 `data/cities.json` + 移除 JS 中城市相关逻辑，恢复无城市态 |

### Phase 1 · Open-Meteo 接口层

| 项 | 内容 |
|---|---|
| 任务 | ① 封装 `weather.js`：按城市坐标构建 API URL → fetch → 解析 JSON；② 提取三个关键字段：`sunrise`/`sunset`（日出日落）、`weather_code`（天气代码）、`temperature_2m`（体感温度）；③ 缓存策略：成功响应缓存 15 分钟，期间不重复请求；④ 错误处理：网络超时 5 秒、HTTP 非 200、JSON 解析失败 → 全部触发降级 |
| 产出 | `weather.js`；单次 fetch 请求获取全部天气数据 |
| 验证 | 控制台可见天气对象输出；断网后不报错，静默降级；同 15 分钟内不重复发请求 |
| 回退 | 删除 `weather.js` + 移除 `<script>` 引用，恢复无天气状态 |

### Phase 2 · 天空引擎动态锚点

| 项 | 内容 |
|---|---|
| 任务 | ① 用真实日出日落时间动态替换黎明（6.3）和日落（18.4）两个锚点的 h 值；② 其余锚点（深夜/清晨/正午/午后/暮色/夜）按比例重新映射到「日出前 → 日升期 → 昼间 → 日落期 → 日落后」五段；③ 保留 ?t=HH:MM 调试参数，新增 ?lat=xx&lon=yy 或 ?city=beijing 调试参数供测试；④ 无天气数据时（断网/未选城市）回退 v0.1 硬编码锚点 |
| 产出 | `sky.js` 重构，锚点映射逻辑独立为 `buildStops(sunrise, sunset)` 函数 |
| 验证 | 不同城市不同季节的天空在「同一时刻」不同；?t= 调试参数叠加 ?city= 可复现任意城市任意时刻的天空 |
| 回退 | git checkout sky.js 恢复 v0.1 版本 |

### Phase 3 · 天气装饰层

| 项 | 内容 |
|---|---|
| 任务 | ① 定义天气代码 → 视觉效果的映射表（晴→无装饰，阴→低饱和度灰滤镜，雨→CSS 雨丝动画，雪→CSS 雪花飘落，雾→高斯模糊薄层）；② 装饰层实现为纯 CSS，由 JS 根据 weather_code 切换 data-weather 属性驱动；③ 装饰层动画遵循 prefers-reduced-motion；④ 天气图标区：在时钟卡眉题区域下方或旁边显示一个小天气图标 + 温度数字 |
| 产出 | 天气装饰 CSS；天气图标（SVG 内联或 Unicode，不引入外部资源）；温度显示 |
| 验证 | 不同天气代码对应不同视觉效果；动画帧率正常（低端机可降级为静态）；prefers-reduced-motion 下装饰层不播放 |
| 回退 | 删除天气装饰 CSS 块 + 移除 data-weather 属性绑定 |

### Phase 4 · 断网降级与体验打磨

| 项 | 内容 |
|---|---|
| 任务 | ① 首次启动无网络 → 静默使用 v0.1 纯时间模式，不弹报错；② 网络恢复后自动重试；③ 城市选择器的定位提示：明确写"手动选择城市，不申请定位权限"；④ 页面 footer 隐私承诺更新：v0.1「零网络请求」→ 改为「天气查询仅用于天空计算，不采集任何个人信息」；⑤ 手动刷新天气按钮（一个不显眼的小图标）|
| 产出 | 降级链路完整，断网体验无感知退化 |
| 验证 | 开飞行模式打开页面 → 正常显示时间天空（无天气装饰）；关飞行模式 → 自动拉取天气；刷新按钮可手动触发重新请求 |

## 关键设计决策（待作者确认）

| # | 问题 | 当前倾向 | 影响 |
|---|---|---|---|
| D1 | 城市列表规模 | ~40 个中国主要城市 | 太多选择器体验差、太少覆盖不足 |
| D2 | 天气刷新频率 | 每 15 分钟自动刷新一次（与缓存一致） | 与 sky.js 的 60 秒天空更新解耦 |
| D3 | 天气装饰的视觉强度 | 克制——装饰层透明度在 0.15~0.35 之间 | 不能喧宾夺主，天空才是主角 |
| D4 | 是否需要显示未来天气预报 | 本期不做（v0.2 仅当前天气） | 避免范围蔓延 |
