# 时念 · v0.5.9 实施计划：许愿池

> 版本：**v0.5.9**　状态：待确认（计划草案）
> 上游依赖：v0.5.6 常驻流星（已交付，可作为许愿入口）
> 缘起：原拟做「点击流星许愿」的交互，经讨论改为在倒数日下方落地**许愿池**——功能更完整、入口更稳定；流星作为彩蛋入口联动。

---

## 一、目标与范围

在**倒数日列表下方**新增**独立模块**「许愿池」：一个存放心愿的本地空间。

> **不并入 v0.5.7 的「提醒」模块**（2026-10-06 讨论确定）：许愿池属**内容层**（与倒数日同为「你写下的东西」），提醒属**配置层**（通知开关与时刻）。
> 内容塞进配置抽屉会导致分类混乱、用户找不到心愿，也违背 v0.5.7「职责单一」的初衷。
> 页面顺序建议：**念想·倒数日 → 许愿池 → 提醒**（内容在前，配置在后）。

**产品定位（2026-10-06 作者澄清）：备忘录式 + 开放式氛围合并**
- **骨架是备忘录**：写下想做的小事 → 完成打勾 → 没完成就空着留到下次，不过期、不自动消失
- **皮肤是许愿**：保留流星、化星升空、温柔文案与夜空玻璃卡的情绪价值
- 一句话概括：**用起来是待办清单，感受上是许愿池**——两者不冲突，本版同时做到

与倒数日的区别（这是产品定位的关键）：

| | 倒数日（现有） | 许愿池（新增） |
|---|---|---|
| 性质 | 有明确目标日期的念想 | 开放心愿，无日期约束 |
| 呈现 | 「还有 N 天 / 已过 N 天」 | 「许下于 … / 已实现」 |
| 时间性 | 倒计时驱动 | 记录与回看驱动 |

**本版范围**：心愿的增 / 删 / 标记已实现、列表展示、数据持久化、纳入备份恢复、基础微交互、与流星的彩蛋联动。

**不在本版范围**：心愿分享、云同步、心愿与提醒打通、AI 建议、心愿分类标签（后续可加）。

## 二、开源调研结论

| 参考项目 | 可借鉴点 |
|---|---|
| [Fumi-no（Happiness Jar）](https://github.com/lauslim12/fumi-no) | **理念最贴合**：每日一条记录、localStorage、**自带备份与恢复**（复制文本/粘贴恢复）、无服务器、隐私优先、完整 a11y、微交互 |
| [心願存錢筒 Wish Jar](https://github.com/chung223/daily-lab) | 单 HTML 文件 + localStorage；玻璃罐发光、星空颗粒的视觉语言与本项目的「液态玻璃 × 星空」高度契合 |
| [wallwish 许愿墙](https://github.com/hiszm/wallwish) / JS 许愿墙实践 | CRUD + 事件委托 + 字数限制 + 删除二次确认等工程细节 |

**明确排除**（与本项目「零后端、纯本地、隐私优先」冲突）：`cf-wishlist`、`wishpage`、`cmintey/wishlist` 等带后端 / 多人共享 / 登录的方案。

**选型：自研零依赖**（与季节彩蛋一致）。上述项目仅借鉴理念与交互细节，不引入代码。

## 三、现状与接入点（已读代码核实）

| 项 | 现状 | 许愿池需改动 |
|---|---|---|
| 念想存储 | `localStorage['shinian.items.v1']`（`app.js` 第 77 行 `KEY`） | 新增 `shinian.wishes.v1` |
| 设置存储 | `shinian.settings.v1` | 可能加许愿池相关设置（如开关） |
| **备份载荷** | `backupPayload()`（第 584 行）：`{app, schema:1, exportedAt, items}` | **必须加 `wishes` 字段**，否则备份会漏掉心愿 |
| 导入恢复 | 第 723 行起，默认合并、同 id 跳过 | 需一并处理 `wishes`；旧备份（无该字段）应安全跳过，不覆盖现有心愿 |
| 清空 | 第 759 行，二次确认 | 确认文案需含心愿条数，清空需一并清除 |
| 条目计数 | 第 208 行 `syncSettingsUI()` | 计数需纳入心愿 |

> ⚠️ **最大工程风险就在备份恢复**：若只加存储而不改 `backupPayload()`，用户备份的心愿会丢失。这是本计划第一优先级。

## 四、功能设计

### 4.1 数据模型
```js
// 单条心愿
{
  id: 'w_' + Date.now() + '_' + rand,  // 唯一
  text: '……',                          // 心愿正文（建议 ≤ 40 字）
  createdAt: '2026-10-05T23:58:00+08:00',
  done: false,                          // 是否已实现
  doneAt: null,
  date: null,                           // 可选：打算哪天去做（仅标注，不产生倒计时）
  targetId: null                        // 可选：可自由选择是否关联某个念想（见「已确认决策」）
}
```

### 4.2 UI（倒数日列表下方 · 默认折叠）

**折叠策略**（2026-10-06 确定，用于控制页面长度）：
- **默认折叠**：收起时只占一行摘要 —— 「已许下 N 个心愿 · 实现 M 个」
- 点击展开／收起；**展开状态由用户自定义并记住**（存 `settings.wishCollapsed`，默认 `true`）
- 首次许愿后自动展开一次，避免用户不知道内容在哪

**已完成条目**（2026-10-06 确定）
- 打勾后**沉底**：未完成始终在前，已完成排到列表底部
- 已完成的折叠为「已完成 N 条」，避免清单越用越乱
- **清理**：单条可删；另给「清空已完成」按钮（二次确认）
- **不自动删**：到 100 条上限时只**提醒**并引导清理——绝不静默删除用户写过的东西
  （完成记录有回顾价值，删除权应始终在用户手上）
```
┌─ 许愿池 ────────────────────────┐
│ [ 写下心愿……        ] [许下]    │
│                                  │
│ ✦ 想去一次北海道      10-05  ☐ 🗑 │
│ ✦ 学会弹《天空之城》  10-01  ☑ 🗑 │
│                                  │
│ 已许下 2 个心愿 · 实现 1 个      │
└──────────────────────────────────┘
```
- 复用现有 `.glass` 玻璃卡与设置面板的 `.set-row` 等既有样式，视觉零割裂
- 输入防抖、`Enter` 提交、空值与超长校验

### 4.3 微交互（零依赖，延续项目惯例）
- **许下时**：心愿化作一颗星升入夜空（CSS/WAAPI，约 600ms）
- **标记已实现**：卡片微光扩散 + 勾选动画
- 全部尊重 `data-no-motion`（减弱动态时静止）

### 4.4 与流星的彩蛋联动（v0.5.6 已备好入口）
- 流星划过时，许愿池入口轻微发亮提示「可以许愿了」
- **点击划过的流星** → 自动聚焦许愿池输入框（快捷许愿）
- 联动为可选增强，不联动也不影响许愿池独立可用

---

### 4.5 心愿到期提醒（与倒数日提醒的分工）

作者确定：心愿**填了日期就要到期提醒**。为避免与倒数日功能重叠，两者分工如下：

| | 倒数日 | 心愿 |
|---|---|---|
| 日期 | **必填**，是核心 | **可选**，只是标注 |
| 倒计时展示 | 有（「还有 N 天」） | **无** |
| 提醒 | 提前 1 天 + 当天，共两条 | 到期当天**一次** |
| 提醒时刻 | 提前 20:00 / 当天 08:00 | 默认 **09:00**（可改） |

- 心愿提醒时刻作为新设置项，与喝水／倒数日提醒**统一归入提醒模块**管理
- **未填日期的心愿不产生任何提醒**
- 提醒文案区别于倒数日：如「今天去做：想吃蛋糕」

## 六、风险登记

| 风险 | 缓解 |
|---|---|
| **备份恢复漏掉心愿**（最高） | S1 第一步就改 `backupPayload()` 与导入逻辑，并写单测覆盖「导出含 wishes」「旧备份安全跳过」 |
| 与倒数日语义重叠 | 计划已明确两者定位差异；若用户希望心愿可绑定念想，走 `targetId` 设计 |
| 数据无上限增长 | **条数上限 100 条**，超出时提示先整理 |
| 隐私 | 与念想一致：纯本地、不上传；README 隐私章节同步更新 |

## 七、验收标准
1. 心愿增删改查正常，刷新后仍在；
2. **备份文本含心愿，导入可恢复；旧备份导入不覆盖现有心愿**；
3. 清空二次确认含心愿条数；设置条目计数含心愿；
4. 移动端 44px 触控达标、玻璃卡对比度满足 WCAG AA；
5. `data-no-motion` 下动效静止；
6. 桌面浏览器验收通过；真机留待后续阶段。

## 八、已确认的决策（2026-10-06 与作者讨论确定）

| 项 | 决策 |
|---|---|
| **模块位置** | **倒数日下方独立模块**，不并入提醒模块（内容层 vs 配置层） |
| **定位** | **备忘录式待办 + 开放式氛围合并**：骨架是清单（写下／打勾／保留），皮肤是许愿（流星／化星／文案） |
| **已完成清理** | 打勾**沉底 + 可折叠**；**不自动删**，到 100 条提醒 + 手动「清空已完成」（二次确认） |
| **折叠** | **默认折叠**，显示「已许下 N 个 · 实现 M 个」；可展开，**状态自定义并记住** |
| **心愿提醒** | **要**：填了日期就到期提醒一次（默认 09:00）；与倒数日分工——心愿不倒计时、只提醒一次 |
| **关联念想** | 可**自由选择**是否关联某个倒数日（`targetId`，可空） |
| **已实现状态** | **要**（勾选 + 暖色反馈） |
| **流星联动** | **点击划过的流星 → 自动聚焦许愿池输入框** |
| **条数上限** | **100 条**，超出时提示先整理 |

> 上述决策已全部确定，待作者发出开工指令后实施。
